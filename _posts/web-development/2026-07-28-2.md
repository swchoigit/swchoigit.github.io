개발할 때는 파일들을 구역별로 나누고, 최종 배포(실행) 할 때는 하나로 합쳐서 내보내는 것이 성능과 유지 보수 모두를 잡는 가장 좋은 방법이다. 현재 사용 중인 Jekyll은 이 작업을 알아서 자동으로 해주고 있다.

## 개발 및 유지 보수 관점
하나의 css 파일에 수천 줄씩 넣으면 나중에 코드를 찾거나 수정하기가 너무 어렵다. `_header.scss`, `_archive.scss`처럼 구역별로 나누어 관리하는 것이 훨씬 효율적이다.

## 웹 브라우저 성능 관점
브라우저가 CSS 파일을 다운로드할 때마다 네트워크 요청(HTTP Request)이 발생하는데, CSS 파일이 10개로 쪼개져 있으면, 브라우저가 서버에 10번 요청을 보내느라 화면이 뜨는 속도가 느려진다. 따라서, 하나의 파일로 합쳐서 1번만 다운로드하게 만드는 것이 브라우저 렌더링 성능에 유리하다.

## Jekyll 동작 방식
Jekyll은 Sass/SCSS 번들러를 내장하고 있다. 개발할 때는 `_sass/` 폴더 안에 목적별로 파일들을 나누어 작성한다. Jekyll이 사이트를 빌드할 때, 분리된 파일들을 읽어와 `assets/css/main.css`라는 하나의 파일로 깔끔하게 합쳐준다.

## 폴더 구조

1. `_sass` 폴더 생성 후 구역별 파일 생성
2. `assets/css/main.scss` 상단에서 `@import`로 불러오기

```css
@import "reset";
@import "variables";
@import "layout";
@import "navigation";
@import "achive";
@import "post";
```
이런 식으로 작성하면 개발할 때는 깔끔하게 분리되어 유지 보수가 편하고, 브라우저가 읽을 때는 Jekyll이 하나의 최적화된 파일로 전달해 주므로 성능 저하가 전혀 발생하지 않는다.
