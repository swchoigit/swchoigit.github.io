## 모델 학습

```python
X = df.drop(columns=['datetime', 'holiday', 'workingday', 'registered', 'casual', 'count', 'countlog'], errors='ignore')
y_log = np.log1p(df['count'])

X_train, X_val, y_train_log, y_val_log = train_test_split(
    X, y_log, test_size=0.2, random_state=42
)

y_val = np.expm1(y_val_log)

print(f"학습용 데이터 개수: {X_train.shape[0]}개")
print(f"검증용 데이터 개수: {X_val.shape[0]}개")
```


### RMSLE 평가 함수 정의

```python
def rmsle(y_true, y_pred):
  y_pred = np.maximum(0, y_pred)
  return np.sqrt(mean_squared_error(np.log1p(y_true), np.log1p(y_pred)))
```

### Random Forest

```python
rf_model = RandomForestRegressor(n_estimators=100, random_state=42, n_jobs=-1)
rf_model.fit(X_train, y_train_log)
pred_log_rf = rf_model.predict(X_val)
pred_rf = np.expm1(pred_log_rf)
score_rf = rmsle(y_val, pred_rf)
print(f"Random Forest RMSLE 점수: {score_rf:.4f}")
```

day_type 그래프의 estimator=len은 대여량이 아니라 행 개수를 표시하고, 습도 구간 그래프도 평균 대여량이 아닌 관측 행 수인 count 열을 y축으로 사용합니다. 따라서 “근무일 이용자가 가장 많다”, “습도 40~60%에서 대여 수가 많다”는 결론을 해당 그래프로 입증하지 못합니다. 요일 그래프도 목~토가 높은데 “수~금”으로 설명했습니다.

다만 기준 선형 모델이 없고 세 모델 모두 사실상 n_estimators=100만 둔 단일 설정이어서 하이퍼파라미터 튜닝이라고 보기는 어렵습니다. 블렌딩 가중치 0.2:0.4:0.4의 선택 근거도 없습니다.

검증은 무작위 8:2 한 번만 사용해 시간 순 일반화 성능을 보장하지 못합니다. 최종 test 예측이나 운영 전략으로 이어지지 않아 최초 목표도 부분적으로만 달성했습니다.

1. day_type과 습도 그래프는 평균·중앙값 대여량과 표본 수를 분리해 다시 작성해야 합니다.
2. 시간 순 검증에서 XGBoost·LightGBM의 깊이, 학습률, 트리 수, 샘플링 비율을 튜닝해야 합니다.
3. 블렌딩 가중치 선택 과정과 개별 전처리의 개선 폭을 별도 검증 또는 OOF 결과로 제시해야 합니다.
4. 최종 test 예측, 구체적 운영 시사점, 한계와 재현 방법을 포함한 독립 보고서를 작성해야 합니다.
