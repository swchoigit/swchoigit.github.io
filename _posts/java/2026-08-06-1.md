## 데이터 선정
Kaggle의 [Hotel booking demand](https://www.kaggle.com/datasets/jessemostipak/hotel-booking-demand?resource=download) 데이터를 활용하였다. (데이터 건수: 119,390건)

## DB Query 연산 소요 시간 측정
1. Maven Central에서 [h2.jar](https://mvnrepository.com/artifact/com.h2database/h2/2.4.240)를 다운로드 받는다.
2. **Project Libraries**에 방금 다운로드받은 `h2.jar` 파일의 의존성을 추가한다.
3. CSV 데이터를 DB 테이블로 로딩한다.
4. DB Query 연산 소요 시간을 측정한다.

``` java
import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.ResultSet;
import java.sql.Statement;

public class InMemoryVsDbPerformanceTest {
    private static final String JDBC_URL = "jdbc:h2:mem:testdb;DB_CLOSE_DELAY=-1";
    private static final String USER = "sa";
    private static final String PASSWORD = "";

    public static void main(String[] args) throws Exception {
        Connection conn = DriverManager.getConnection(JDBC_URL, USER, PASSWORD);
        Statement stmt = conn.createStatement();

        // 1. 데이터 10만 건 삽입
        stmt.execute("CREATE TABLE hotel_booking AS SELECT * FROM CSVREAD('src/hotel_bookings.csv')");
        
        long startTime = System.currentTimeMillis();

        // 2. 국가별 예약 건수 집계
        ResultSet rs = stmt.executeQuery("SELECT country, COUNT(*) FROM hotel_booking GROUP BY country");

        while (rs.next()) {
            String country = rs.getString(1);
            int count = rs.getInt(2);
        }

        long endTime = System.currentTimeMillis();

        System.out.println("DB Query 연산 소요 시간: " + (endTime - startTime) + " ms");

        conn.close();
    }
}
```

### 결과
``` text
DB Query 연산 소요 시간: 118 ms
```

## Java In-Memory 연산 소요 시간 측정

``` java
import java.io.BufferedReader;
import java.io.FileReader;
import java.io.IOException;
import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

public class InMemoryVsDbPerformanceTest {
    private static final String JDBC_URL = "jdbc:h2:mem:testdb;DB_CLOSE_DELAY=-1";
    private static final String USER = "sa";
    private static final String PASSWORD = "";

    public static void main(String[] args) throws Exception {
        List<String[]> dataList = new ArrayList<>();

        // 1. CSV 파일 읽기
        try (BufferedReader br = new BufferedReader(new FileReader("src/hotel_bookings.csv"))) {
            String line = "";
            br.readLine();

            while ((line = br.readLine()) != null) {
                dataList.add(line.split(","));
            }
        } catch (IOException e) {
            e.printStackTrace();
        }

        long startTime2 = System.currentTimeMillis();

        Map<String, Integer> map = new HashMap<>();

        // 2. 데이터 담기
        for (String[] row : dataList) {
            String country = row[13];
            map.put(country, map.getOrDefault(country, 0) + 1);
        }

        long endTime2 = System.currentTimeMillis();

        System.out.println("Java In-Memory 연산 시간: " + (endTime2 - startTime2) + " ms");
    }
}
```

### 결과
``` text
Java In-Memory 연산 시간: 59 ms
```

## DB 연산 vs Java In-Memory 연산 선택 기준
과거 프로젝트 당시, 대용량 데이터 연산 속도가 너무 느려서 DB Query 연산 방식이 아닌 Java In-Memory 연산 방식으로 변경했더니 약 10배의 속도 향상을 경험했다. 이번 테스트에서는 이미 데이터를 `List`에 저장한 상태에서 순수 연산 시간만 측정했기 때문에 네트워크 통신 시간은 제외 되었다. 만약 실제 운영 환경처럼 외부 DB 서버를 사용해서 똑같이 테스트했다면, DB 연산 속도가 압도적으로 빨랐을 것이다. Java는 데이터를 읽을 때마다 DTO 객체를 Heap 메모리에 할당하므로 GC(Garbage Collector) 부하가 발생한다. 반면 C/C++ 기반 DB 엔진은 객체 생성 오버헤드가 거의 없기 때문에 대부분의 경우는 DB 연산이 훨씬 빠르다. 따라서 기본적으로는 DB에서 데이터를 처리하되, 이미 필터링된 데이터를 가공하거나 비즈니스 로직이 복잡한 상황에서는 Java In-Memory 연산을 고려해 볼 수 있다.

## `HashMap` vs `List`
### `List`
* 용도: 데이터를 순서대로 저장하거나, 전체 데이터를 처음부터 끝까지 순회하여 단순 필터링할 때
* 장점: 메모리 구조가 가볍고 간단함 
* 단점: 특정 데이터를 찾으려면 처음부터 뒤져야 하므로 시간이 오래걸림

### `HashMap`
* 용도: 특정 Key로 데이터를 찾거나, 그룹별로 묶어서 개수나 합을 구할 때
* 장점: 해시 함수를 통해 데이터 개수와 상관없이 즉시 탐색 및 집계 가능
* 단점: 데이터를 저장할 때마다 내부적으로 `Node` 객체를 생성하므로 `List` 대비 Heap 메모리 점유율이 큼
