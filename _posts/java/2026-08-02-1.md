① DB 연산 vs Java 메모리 연산 성능 비교 (Everjoy 경험 관련)
Everjoy 프로젝트에서 작성하셨던 **"DB 쿼리 로직을 Java 메모리 연산으로 옮겨 속도를 개선한 경험"**을 직접 실험해서 블로그 포스팅 및 깃허브 코드로 남기는 것입니다.
* 실험 내용: 10만 건 이상의 가상 데이터를 준비하고, 아래 두 경우의 실행 시간을 측정합니다.
    1. SQL 쿼리에서 GROUP BY, SUM, Complex Expression 등을 이용해 DB가 직접 계산하게 한 경우
    2. 단순 Select 후 Spring/Java Stream API 또는 Loop 문을 통해 Java 메모리(JVM)에서 계산한 경우
* 블로그 포인트: 데이터 건수별(1천 건 vs 10만 건 vs 100만 건) 처리 속도 비교 차트, DB CPU/메모리 사용량 vs API 서버 CPU/메모리 사용량의 Trade-off 분석.
② Legacy JSP SQL Direct Call vs Spring Boot + JPA/MyBatis 구조 비교
WINIA/Everjoy에서 경험하셨던 JSP 내 직접 SQL 작성 방식과 현대적 백엔드 구조의 차이점을 간단한 코드로 비교하는 것입니다.
* 실험 내용:
    1. JSP에 DB connection을 맺고 Query를 직접 날리는 레거시 방식
    2. Service / Repository 층을 분리한 깔끔한 Layered Architecture
* 블로그 포인트: 유지보수성, 테스트 코드 작성 가능 여부, SQL Injection 등 보안 및 성능 관점에서의 비교 정리.
③ Web vs Mobile UI/UX 대응을 위한 API 응답 구조 설계 (WINIA 경험 관련)
웹 환경과 모바일 환경을 모두 대응할 때 API를 어떻게 다르게 설계할 것인가에 대한 포스팅입니다.
* 실험 내용:
    * 화면 구성이 다른 Web과 Mobile(Android)의 요구사항을 맞추기 위한 BFF(Backend For Frontend) 개념 맛보기
    * 또는 Web용 API와 Mobile용 응답 DTO를 구분해서 전달하는 깔끔한 Controller 설계 연습
* 블로그 포인트: 화면 단이 다를 때 백엔드 API를 어떻게 설계하는 것이 중복을 줄이고 효율적인가에 대한 고민 정리.
2. ⚡ 백엔드 기본기를 보여주는 가벼운 토픽
④ @Async 비동기 처리 시 ThreadPool 설정에 따른 성능 및 동작 차이
* 실험 내용: @Async 사용 시 기본 설정(SimpleAsyncTaskExecutor - 매번 쓰레드 생성)과 ThreadPoolTaskExecutor를 커스텀 설정했을 때의 차이 측정.
* 블로그 포인트: 요청이 폭주할 때 쓰레드가 어떻게 생성되는지, Queue capacity가 넘어갔을 때 어떤 예외(RejectedExecutionException)가 발생하는지 테스트 코드로 증명.
⑤ JPA N+1 문제 발생 조건과 Fetch Join / EntityGraph 적용 전후 비교
* 실험 내용: 1:N 연관관계 엔티티를 만들고, 단순 findAll() 호출 시 발생하는 쿼리 개수와 Fetch Join 적용 후 쿼리 개수 및 실행 시간 비교.
* 블로그 포인트: 쿼리 로그(Hibernate SQL Log) 캡처 및 성능 측정 기록.
